# labcheck: перевірка лабораторної перед здачею

Інструмент перевіряє папку з роботою за текстом завдання: точні шляхи файлів, відповіді на всі питання, залишені заготовки, ключі, вагові файли й індекси, секції звіту. Звичайний код робить усе, що можна перевірити точно. AI (рівень 1, один запит на крок) розбирає текст завдання й оцінює, чи відповідь стосується питання; кожну цитату моделі код звіряє з текстом.

Звіт і докази: [`../report.md`](../report.md), [`../evidence/`](../evidence/).

## Вимоги

- Python 3.10 або новіший (перевірено на 3.13). **Зовнішні пакети для роботи не потрібні.**
- Для AI-кроків: ключ до будь-якого OpenAI-сумісного API (за замовчуванням Gemini). Без ключа працюють усі детерміновані перевірки.
- Для тестів: `pip install pytest`. Для графіка: `pip install matplotlib`. Для перевірки довжини відео: `ffprobe` (входить у ffmpeg), якщо є.

## Швидкий старт без AI (без ключа й мережі)

```bash
cd mkr1/solution
python -m labcheck check <корінь_репозиторію_або_папка_lab6> --spec specs/lab6.json --no-ai
```

На Windows замість `python` можна `py`. `<корінь_репозиторію>` — тека, де лежить `lab6/`; запуск з самої теки `lab6` теж працює. Код завершення: 0 — помилок немає, 1 — є помилки `[ERR]`, 2 — неправильні параметри.

Готові специфікації: `specs/lab5.json`, `specs/lab6.json`, `specs/mkr1.json`. Приклад для самої МКР (запуск із `mkr1/solution`):

```bash
python -m labcheck check .. --spec specs/mkr1.json --no-ai
```

## Підключення AI

```bash
copy .env.example .env        # Linux/macOS: cp .env.example .env
# відкрийте .env, вставте LLM_API_KEY; LLM_MODEL підкаже наступна команда
python -m labcheck doctor
```

`doctor` перевіряє ключ і модель і робить тестовий запит. Після цього `check` сам використовує AI, якщо ключ є (вимкнути: `--no-ai`).

| Команда | Що робить |
|---|---|
| `python -m labcheck check <тека> --spec specs/lab6.json` | детерміновані перевірки + AI-суддя відповідей |
| `python -m labcheck check <тека> --assignment inputs/lab6_assignment.txt --spec specs/lab6.json` | AI розбирає текст завдання; якщо не вийшло, береться `--spec` |
| `python -m labcheck extract-spec inputs/lab6_assignment.txt --out my_spec.json` | зберегти розбір завдання як специфікацію |
| `python -m labcheck check ... --md звіт.md --json звіт.json --history history.jsonl --label назва` | зберегти результат і дописати рядок в історію запусків |
| `python -m labcheck bench static` | бенчмарк підкинутих дефектів (без AI) |
| `python -m labcheck bench ai` | якість AI-кроків (потрібен ключ) |

Для нового завдання покладіть його текст у файл і запустіть `check --assignment файл.txt --spec запасна.json` (`--spec` потрібна лише як запасний варіант).

## Один запуск усіх доказів: `demo_run.py`

```bash
python demo_run.py            # вперше без кешу; повторні запуски беруть відповіді з кешу
python demo_run.py --fresh    # завжди нові запити до моделі (кеш не пишеться; після збою сервісу краще запускати БЕЗ --fresh)
python demo_run.py --lab6 D:\repo\lab6   # додатково перевірити вашу теку lab6 з AI-суддею
```

Скрипт по черзі: перевіряє доступ до AI; запускає бенчмарк підкинутих дефектів; розбирає 3 завдання AI і порівнює з еталонами; оцінює 50 відповідей AI-суддею; перевіряє саму папку `mkr1` (12 відповідей звіту проти питань МКР-1); збирає `report.md`, підставляючи виміряні числа. Логи лягають у `../evidence/ai_run/`, історія запусків — у `../evidence/history.jsonl`. Якщо AI недоступний, скрипт зупиняється з поясненням; `python finalize_report.py` усе одно збере звіт, позначивши AI-частину як невиміряну.

Оцінки «з голови» (час ручної перевірки тощо) лежать у `estimates.json`; змініть і виконайте `python finalize_report.py`.

## Тести

```bash
python -m pytest -q
```

Покрито: детерміновані перевірки, парсинг питань і кодувань, `.gitignore`, клієнт AI на справжньому локальному HTTP-сервері (повтори на 429/503, помилка ключа, кеш, пошкоджений кеш, недоступний сервер), захист від вигадок моделі (вигадані шляхи й питання, цитата не з тексту), CLI та коди завершення.

## Структура

```
solution/
  labcheck/        код: spec, notebook, static_checks, llm, ai_steps, report, bench, cli
  specs/           еталонні специфікації завдань (запасний варіант і еталон для оцінки AI)
  inputs/          тексти завдань (лаби 5, 6, МКР-1)
  bench_data/      реальні відповіді лаби 6 для бенчмарку AI-судді
  scripts/         make_gold_specs.py, make_judge_data.py, real_runs.py
  tests/           pytest
  demo_run.py, finalize_report.py, make_chart.py, report.template.md, estimates.json
```

## Обмеження й приватність

- Інструмент перевіряє **наявність** відповіді по суті, а не її правильність; AI-вердикти лише попередження.
- З AI на сервіс відправляється текст завдання й текст відповідей із ноутбуків (не ключі). Якщо це небажано, використовуйте `--no-ai`.
- `.env` із ключем у `.gitignore`. Не публікуйте ключ; якщо він потрапив у чат, скріншот чи репозиторій, відкличте його й створіть новий.
- Перевірено лише на Linux; на Windows консоль перемикається на UTF-8 автоматично.
